# Code of Conduct

## Scope

This is currently a 3-person academic team project, not yet open to external contributors (see [`CONTRIBUTING.md`](CONTRIBUTING.md)). This document states the expectations the team already holds itself to, and the baseline that will apply if and when the project opens to outside contributions — it's not a response to any incident, just something worth having written down rather than assumed.

## Expected Behavior

- Communicate directly and respectfully, especially when disagreeing about a technical decision — this project's own [ADRs](docs/architecture/adr/) exist partly because genuine disagreements about hard tradeoffs (model selection, architecture) are normal and worth recording honestly, not smoothing over.
- Give credit accurately. Per-area ownership is tracked in [`.github/CODEOWNERS`](.github/CODEOWNERS); don't misrepresent who did what, in commits, documentation, or elsewhere.
- Raise concerns about code, process, or conduct directly with the person involved or the project owner (see [`SECURITY.md`](SECURITY.md) for the current primary contact) rather than letting them go unaddressed.

We value respectful technical discussion, constructive feedback, and evidence-based decision-making throughout the project.

## Unacceptable Behavior

Harassment, discriminatory language or jokes, personal attacks, publishing others' private information without consent, or any conduct that would reasonably make a collaborator feel unsafe or unwelcome.

## Enforcement

At this project's current 3-person scale, conduct concerns are handled directly between team members or escalated to the project owner. There is no formal enforcement committee or process — this will be revisited if and when the project grows beyond its current team.
